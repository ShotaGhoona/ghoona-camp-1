## 🚀 6つのドメインの役割分担

### 🧑‍💼 **User Domain**（ユーザー管理）
- **責務**: アイデンティティ、プロフィール、SNS連携
- **制約**: Clerk認証必須、メールアドレス必須、URL形式チェック
- **価値**: 確実な認証基盤、豊富なプロフィール機能

### 📅 **Event Domain**（イベント管理）  
- **責務**: 朝活イベントの作成・参加管理
- **制約**: 7種類のイベントタイプ、時間整合性、定員管理
- **価値**: 構造化されたイベント体験、参加状況の透明性

### 🎯 **Goal Domain**（目標管理）
- **責務**: 個人目標の設定・追跡
- **制約**: 期間の論理的整合性、公開/非公開制御
- **価値**: パーソナライゼーション、プライバシー保護

### 🏅 **Title Domain**（称号管理）
- **責務**: 成果認定・ゲーミフィケーション
- **制約**: 8段階固定、日英バイリンガル、必要日数検証
- **価値**: モチベーション向上、長期エンゲージメント

### 📊 **Attendance Domain**（参加記録）
- **責務**: Discord参加の自動追跡・統計
- **制約**: 朝活時間帯検出、連続記録整合性、現実的時間制限
- **価値**: 客観的成果測定、自動化による手間削減

### 🔔 **Notification Domain**（通知管理）
- **責務**: ユーザーコミュニケーション
- **制約**: 4種類の通知タイプ、個別設定可能、デフォルト21:00
- **価値**: 適切なタイミングでの動機付け、カスタマイズ可能

## 💎 実装の技術的価値

### 🎨 **YAGNI原則の徹底**
- エンティティは最小限のコンストラクタのみ
- 複雑なビジネスロジックはアプリケーション層に委譲
- 必要になった時点で機能追加可能な拡張性

### 🔒 **型安全性による品質保証**
```go
// コンパイル時にビジネスルール違反を検出
type TitleLevel int  // 1-8の範囲外は型レベルで防止
type Platform string // 定義外のプラットフォームは使用不可
```

### 🌍 **国際化対応**
```go
// 日英バイリンガル対応
nameJP: "朝活の伝説"
nameEN: "Morning Legend"
```
